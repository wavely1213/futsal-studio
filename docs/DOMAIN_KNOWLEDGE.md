# DOMAIN_KNOWLEDGE.md — 도메인 지식

> **목적**: 이 서비스의 용어·비즈니스 규칙·불변식을 기록한다. 코드만 봐서는 알 수 없는
> "서비스가 왜 이렇게 동작해야 하는지"의 원천. AI는 도메인 개념이 등장하는 작업 전에
> 이 문서를 확인하고, 여기 정의된 용어·규칙과 다르게 구현하지 않는다.
>
> **갱신 시점**: 새 개념·규칙이 확정될 때마다 즉시. 규칙 변경은 `DECISION_LOG.md`에도 기록.

## 1. 용어집 (Glossary)

> 코드 네이밍은 반드시 이 표의 영문 표기를 따른다. 같은 개념 = 같은 이름.
> 화면 문구는 이 표의 한국어 용어를 쉬운 해요체로 쓴다 (예: 시퀀스 → 화면에서는 "편집본").

### 영상·편집

| 용어 (한국어) | 코드 표기 | 정의 |
|---|---|---|
| 롱폼 | `long` | 가로 16:9 일반 영상. 내보내기 1920×1080(기본 프리셋), 썸네일 1280×720 |
| 쇼츠 | `shorts` | 세로 9:16 영상. 1080×1920, 3분 이하 (BR-001). 썸네일 편집기만 `short`를 쓴다 (`KNOWN_ISSUES.md` I-005). 새 코드는 `shorts` |
| 우리 채널 | `CONFIG["channel_url"]` | 풋살사관학교 채널. 불러온 목록은 제목 틀 학습용으로 `channel_cache.json`에 기억한다 |
| 소재 찾기 | `core.list_videos` | 채널(우리 채널 또는 다른 유튜버)의 영상 목록을 조회수 순으로 불러오기 |
| 보관함 | `core.VIDEOS` (`videos/`) | 받은 영상·촬영 원본·묶은 영상이 있는 폴더. 모든 데이터의 키는 이 폴더의 **파일 이름**이고, 영상별 폴더·파일 이름은 `core.adir(name).name` |
| 촬영 원본 | — | 사용자가 직접 찍어 보관함에 넣은 파일 (YouTube에서 받은 영상이 아닌 것) |
| 복사 중 | `copying` (`intake.copying`·`busy`) | 보관함 폴더에 아직 들어오는 중인 파일(탐색기 복사·카메라 가져오기·녹화). 고를 수 없고 편집점 찾기·묶기를 하지 않는다 (BR-019) |
| 못 쓰는 형식 | `unusable` (`intake.UNUSABLE_EXTS`) | 영상이지만 아직 쓸 수 없는 형식(캠코더 `.MTS`·`.AVI`·`.WMV` 등). 보관함에 '이 형식은 아직 못 써요' 줄로만 보인다. 쓸 수 있는 형식은 `core.VIDEO_EXTS`(mp4·mov·m4v·mkv·webm) |
| 파일이 바뀌었어요 | `changed` (`file_sig.json`) | 편집점을 찾은 뒤 영상 크기나 수정 시각이 바뀜 — 덜 복사된 채 찾았을 수 있어 [편집점 다시 찾기]를 권한다 (BR-019) |
| MP4로 바꾸기 | `intake.convert` · `POST /api/convert` | 못 쓰는 형식(.MTS 등) 줄의 버튼. 편집할 수 있는 MP4(H.264 + AAC)로 바꿔 보관함에 넣고, 원본은 보관함 안 '바꾸기 전 원본' 폴더로 옮긴다 (BR-019) |
| 영상 출처 | `source` (`videos/sources.json`, `source.describe`) | 보관함 영상이 어디서 왔는지: `own` 풋살사관학교(우리 채널) · `other` 다른 채널 · `footage` 내 촬영본(촬영 원본·묶은 영상·유튜브 이름 꼴이 아닌 파일) · `unknown` 모름('확인 중'/'알 수 없음'). 직접 고른 것(`manual`)이 우선 (BR-014) |
| 채널 묶음 | `channelKey` · `channels` | 다른 채널을 채널별로 나누는 열쇠: 채널 id(UC…) → 없으면 `h:@핸들` → `n:채널이름`(띄어쓰기·대소문자 무시). 이름이 바뀌어도 채널 id 가 같으면 한 묶음이고 이름은 마지막 것. 채널마다 고정 색 번호 `color`(0~7) |
| 촬영본 묶기 | `bundle.make_bundle` | 여러 파일로 나뉜 한 번의 촬영을 찍은 순서대로 한 영상으로 이어 붙이기 (BR-008) |
| 편집점 찾기 | `core.analyze` | 받아쓰기 + 무음 + 음량 피크 분석. 끝나면 1차 가편집까지 자동으로 만든다 |
| 받아쓰기 | `transcript` (`transcript.json`, `subtitles.srt`) | faster-whisper 한국어 결과 `[{start, end, text, words}]`. `words`는 단어마다 `{w, s, e, p}`(글자·시작·끝·확신)이고 `text`는 단어를 띄어 이은 것과 같다. 예전 받아쓰기는 `words`가 없다 |
| 용어 사전 | `dict.json` (`captions.load_dict`·`save_dict`, `/api/dict`) | 받아쓰기에 미리 알려 줄 풋살 용어·이름(`terms`)과 자주 틀리게 받아쓰는 말 고치기(`fix` {틀린 말: 바른 말}). 보관함 화면의 '용어 사전'에서 고친다 |
| 편집점 | `silences` · `loud_peaks` | 자르거나 살릴 만한 곳. **컷 후보** = 조용한 구간(`silences`), **하이라이트** = 소리가 갑자기 커진 곳(`loud_peaks`, 환호·슈팅·웃음) |
| 가편집 (1차 가편집) | `editor.auto_sequences`, `auto: "rough"` | 편집점 찾기 직후 자동으로 만드는 편집본: 롱폼 가편집 1개 + 쇼츠 1~3개 |
| 군더더기 정리 | `tidy` (`recommend()["tidy"]`) | 추임새·같은 말 반복·긴 무음(·NG 테이크·슬레이트·말더듬)을 뺀 롱폼 컷 목록 (원본 시각). 편집실 버튼은 이 목록 밖의 원본을 **지금 편집본의 V1 원본 클립에서만** 뺀다 (`editor.html` `tidySeq` · 쇼츠는 그 구간 안 · D-059) |
| 추임새 | `FILLERS` · `takes.find_fillers` | "아·어·음·자·네…"처럼 뜻 없는 말. 구간 전체가 추임새면 구간째, 단어 시각이 있으면 말 사이에 홀로 떨어진 단어('음'·'어'·'그'·'아' …)도 뺀다 |
| NG 테이크 | `takes.find_junk` ("다시 찍은 앞 테이크") | 3~60초 뒤에 같은 말로 다시 찍었을 때의 앞 테이크. 가편집에서 뺀다. 슬레이트 말 없이 다 말한 설명 사이에 시범이 있으면 NG 가 아니다 (BR-022) |
| 슬레이트 | `takes.is_slate` | "다시 할게요"·"NG"·"잠깐만요" 같은 촬영용 말. 가편집에서 뺀다 ("천천히 다시 할게요" 같은 연습 안내는 아님) |
| 영상 밖 말 | `takes.find_offscript` · `recommend()["offscript"]` | 영상 내용이 아닌 말 (BR-060). **촬영 준비 말** = 첫 인사·주제 소개 앞의 '녹화되고 있어?'·'빨간불 들어왔지?'와 대답 · **촬영 끝 말** = 마지막 끝인사 뒤의 '컷, 수고했어요'·'한 번 더 찍을까' · **영상 밖 안내 말** = 구독·좋아요 부탁(`cta`), 레슨·인스타·DM 홍보(`promo`). 편집실 추천 탭 '영상 밖 말'에 보임 |
| 문장 (가편집 계산) | `captions.split_sentences` | 받아쓰기 한 구간을 단어 시각으로 문장 끝('~요·~니다·~죠'·마침표)·1초 넘는 쉼에서 나눈 것. 가편집·쇼츠 경계 계산만 이것으로 하고 받아쓰기 파일은 그대로 (D-101) |
| 반응 말 | `editor.REACTION` | 시범을 보고 하는 말 ('나이스!'·'아이고, 공이 뒤로 갔네요'·'들어갔어요'·'아깝다'·'봤죠?'). 쇼츠는 그 앞의 말 없는 시범(원인)과 함께 둔다 (BR-061) |
| 말더듬 | `takes.find_junk` ("말더듬") | 같은 짧은 말(또는 끊긴 첫마디)을 1초 안에 다시 한 것. 마지막 것만 남긴다. 숫자 세기·리듬 말·구령·환호('하나, 둘, 셋!'·'나이스!')와 외친 말은 말더듬이 아니다 (BR-022) |
| 편집 프로젝트 | `project` (`projects/<stem>.json`) | 영상 하나의 편집실 저장 파일 (자막·시퀀스·미디어·`rev`) |
| 시퀀스 (편집본) | `sequence` (`proj.sequences[]`) | 편집실의 편집본 하나. `format`·트랙·클립(`items`)·전환·마커·제목·도형 |
| 펀치인 (확대 컷·줌 컷) | `zoom` (컷의 `zoom` 표시, `editor._shots`·`_punch`·`_split_rhythm`, 스타일 `zoomCutsPerMin`·`avgZoom`) | 같은 장면을 컷 자리에서 확대해 리듬을 주는 컷. 자동 가편집은 잘라 낸 자리(점프 컷)마다, 그리고 목표 컷 길이(`splitShot`·`zoomEvery`)를 넘는 말을 자막이 바뀌는 곳에서 나눌 때마다 확대/원래 크기를 뒤집는다 (BR-022) |
| 자막 | `captions` · `captionStyle` | 받아쓴 대사로 만든 화면 글자. 단어 시각으로 나눈 자막은 `words`(노래방 효과용)를 함께 가진다 |
| 자막 나누기 | `captions.chunk`·`split_text`·`from_segments` | 받아쓴 단어·이미 있는 자막을 한 줄 자막으로 나누기 (BR-013) |
| 자막 띠 | `captionPos` · `captionBands` (스타일) | 자막이 깔리는 가로 영역(위·가운데·아래). 스타일 분석은 화면을 가로 띠 6개로 나눠 글자가 있는 띠를 찾는다. 편집실 도형의 '제목 띠·하단 띠'(`shapes`)는 글자 뒤에 까는 색 띠 |
| 쇼츠 훅 (큰 제목) | `titles` · `editor._hook` | 쇼츠 위쪽 큰 글자 ("주제어 꿀팁" / "주제어!") |
| 화면 구성 | `layout.mode` = `fill` / `box` / `blur` | 쇼츠에 가로 원본을 넣는 방식: 풀샷 자르기 / 가로 맞춤 + 위아래 박스 / 블러 배경 |
| 마커 | `markers` | 편집실 타임라인 표시. 이름 붙인 마커는 올리기 키트의 챕터가 된다 |
| LUFS | `master.lufs` · `lufs` | 소리 크기 단위. 유튜브는 약 -14 LUFS로 맞춰 틀고, 작은 소리는 키워 주지 않는다 (자동 가편집 목표 -14~-13 · 검수는 -16 밑이면 경고, BR-022) |
| 내보내기 | `editor.export` | 편집본 → `out/`에 mp4·SRT·프리미어 XML |
| 검수 | `qa.check_video` | 내보낸 영상 자동 점검(규격·길이·검은 화면·멈춘 화면·소리 끊김·LUFS·피크) → 점수 |
| 미리보기 파일 | `proxy` | 편집실 재생용 가벼운 사본 |
| 작업 | `JOB` · `app.start_job` | 화면에서 시작한 긴 처리. 한 번에 하나 (BR-010) |
| 실패 카드 | `fail` (`trouble.explain`, `ui.html` `showFail` · 편집실 `showEdFail`) | 작업이 실패하면 그 화면에 남는 카드: 쉬운 해요체 한 줄 + 할 일 버튼(다시 하기·로그인 정보로 다시 받기·로그인 정보 없이 다시 하기·업데이트 확인·폴더 열기·주소 다시 넣기·쇼츠/긴 영상으로 다시 불러오기·작업 기록 보기·studio.log 위치 열기). ✕ 나 그 화면의 새 작업으로 닫힌다 (BR-020) |
| 로그인 정보로 받기 | `cookies` (`trouble.BROWSERS`) | YouTube 가 막을 때 사용자가 고른 브라우저(크롬·엣지·웨일·파이어폭스)의 YouTube 로그인 정보(쿠키)로 받기. 기본은 '안 씀' (BR-009·D-009) |
| 실행 표시 | `studio.running.json` (`studiolog.session_start`) | 앱이 켜져 있는 동안 작업 폴더에 있는 표시. 정상 종료(창 닫기 — 작업 중이면 확인을 받은 뒤 · 업데이트 재시작)면 지워지고, 다음에 켤 때 남아 있으면 '갑자기 꺼짐'으로 studio.log 에 남긴다 (D-044) |
| 작업 폴더 / 완성본 폴더 | `core.WORK` / `core.OUT` (`out/`) | 사용자 데이터 전체(`~/풋살사관학교_작업`) / 내보낸 영상·썸네일·올리기 키트 |
| 다운로드 엔진 / YouTube 해석 도구 | yt-dlp (`core.update_engine`) / Deno (`core.ensure_deno`) | 영상 받기 부품. 앱이 알아서 최신으로 관리한다 (D-008) |

### 스타일 배우기

| 용어 (한국어) | 코드 표기 | 정의 |
|---|---|---|
| 레퍼런스 | `refs[]` | 스타일을 배우려고 담은 다른 유튜버 영상 (보통 학습용 영상 · 보관함 영상도 쓸 수 있음) |
| 학습용 영상 | `refs.py` (`WORK/refs/`) | 스타일 배우기에만 쓰는 영상 보관함. 편집용 보관함(`videos/`)과 따로 있고 보관함·편집점·편집실·썸네일·올리기 목록에 나오지 않는다. 채널별 폴더·색 |
| 배운 뒤 파일 지우기 | `refs.prune` · `pruned`·`sig` | 학습용 영상 파일만 지우고 분석 기록과 그때 파일 지문을 남김 → 스타일은 그대로, 다시 배울 때 남은 기록을 씀 |
| 학습용으로 옮기기 | `refs.move_from_library` | 보관함의 다른 채널 영상(+ 분석 폴더)을 학습용 영상으로 옮김. 풋살사관학교·내 촬영본·출처 모름은 사용자 확인 뒤에만, 편집실 프로젝트에서 쓰는 영상은 옮기지 않음 |
| 보관함으로 (되돌리기) | `refs.restore` | 학습용 영상(+ 분석 폴더)을 편집용 보관함으로 되돌림 |
| 원본 (학습용) | `original` | 확인하고 옮긴 풋살사관학교·내 촬영본·출처 모름 영상. 다시 받을 수 없으니 '배운 파일 지우기'에서 빼고, 지우기는 한 번 더 확인 |
| 추천 채널 · 방향 | `ref_channels.json` | 채널 조사(2026-10-07) 51곳(풋살 특화·축구 레슨·기술·축구 예능·챌린지·리뷰·브이로그·분석)과 방향 A(레슨 + 예능 MSG형)·B(챌린지·대결형)·C(쇼츠 집중형)별 먼저 배울 영상 |
| 스타일 (스타일 프로필) | `profile` (`styles/<이름>.json`) | 레퍼런스에서 잰 값의 합: 컷 길이·줌 컷·말 사이 공백·자막 위치와 색·LUFS·말 빠르기. 여러 영상이면 평균 |
| 형식별 스타일 | `formats{long, shorts}` · `refs[].format` · `style.ref_format` | 쇼츠와 긴 영상을 섞어 배운 스타일의 형식마다 따로 합친 값. 롱폼 가편집은 긴 영상 값, 쇼츠 가편집은 쇼츠 값을 쓴다 (BR-063 · D-102) |
| 편집 값 | `style.edit_params()` | 프로필을 자동 가편집 입력으로 바꾼 값 (`keepPause`·`zoomEvery`·`zoomScale`·`captions`·`captionPos`·`captionColor`·`lufs`·`targetShot`) · 형식별 스타일이면 `byFormat{long, shorts}` 도 |

| 방향 비교 | `forecast.plans` · `_preset_refs` | 방향 A/B/C 를 같은 운으로 계산한 다음 목표(12개월) 가능성 + 참고 채널 보통 조회수. 주당 개수만 계산에 들어가 개수가 같으면 같은 % |

| 민감도 | `sensitivity` | 같은 운(공통 난수)으로 계획만 바꿔 다시 계산한 확률 차이. 두 끝을 각각 반올림한 값의 차이로 적고(%포인트), 3%p 안쪽이거나 반올림한 두 끝이 같으면 '거의 차이 없어요' |
| 목록 받은 시각 | `listedAt` (`strategy.listed_at`) | 구독자·조회수 목록을 마지막으로 받은 시각. RSS 만 받은 날은 바뀌지 않는다 — '오래됨'·새로 고칠 차례·우리 채널 하루 한 번 기록은 이것으로 (BR-016) |
| 점검 · 기록 | `checkups.json` · `history.jsonl` | 점검 = 3일 넘게 지난 마지막 점검(없으면 전략을 시작한 날) 뒤 계획 vs 실제와 잘 되는 것/안 되는 것/바꿀 것 (BR-017). 기록 = 새로 고칠 때마다 채널별 한 줄 — 구독자는 그날 목록에서 새로 받았을 때만 |

### 풋살 용어

> 새 풋살 용어는 스튜디오 '용어 사전'(작업 폴더 `dict.json`)에 넣거나 `hooks.SKILLS`(기술 이름)·`hooks.TERMS`에 더하면 제목·태그 주제어로 잡힌다 (긴 말부터 찾고, 띄어 쓴 이름은 붙여 써도 찾고, 2글자 이하는 다른 낱말 안에 붙어 있으면 세지 않음). `TERMS`는 편집실 강조 자막·기획 분석·채널 전략도 쓰므로 기술 이름은 `SKILLS`에 넣는다.

| 용어 (한국어) | 코드 표기 | 정의 |
|---|---|---|
| 피벗 (피보, pivô) | `피보` | 최전방 공격수. 골대를 등지고 공을 받아 지키고 연결하거나 마무리한다 |

| 픽소 (fixo) | `픽소` | 최후방 수비수 |

| 킥인 | `킥인` | 터치라인 밖으로 나간 공을 발로 차서 다시 시작하는 것 (풋살은 스로인 대신) |
| 토킥 | `토킥` | 발끝으로 차는 슛. 동작이 짧고 빠르다 |

## 2. 회원 등급·권한 체계

로그인·회원이 없는 **1인용 로컬 앱**이다. 권한은 "누가 무엇을 할 수 있는가"로만 나뉜다.

| 역할 | 누구 | 할 수 있는 것 |
|---|---|---|
| 사용자 | 최경진 감독 등 (Windows PC, 비전문가) | 앱의 모든 기능. 업데이트 받기. 배포는 못 함 |
| 소유자 (관리자) | 개발자 | `release.sh` 배포, `manifest.json`, 업데이트 주소(`config.json`의 `update_manifest_url`) |
| 이 PC의 앱 창 | `127.0.0.1`의 화면 | 서버 API 호출. Host가 `127.0.0.1:PORT`·`localhost:PORT`인 요청만 받고, POST는 같은 출처만 받는다 (다른 사이트·다른 PC 차단) |

## 3. 비즈니스 규칙 (Business Rules)

> 각 규칙은 번호를 부여하고, 구현·테스트에서 이 번호를 참조한다 (예: `BR-001`).

- **BR-001 쇼츠 규격**: 쇼츠는 세로 9:16(1080×1920)이고 3분(180초) 이하다.
  - 검수: 비율이 다르거나 3분을 넘으면 오류, 1분을 넘으면 주의다.
  - 원본 영상으로 만드는 올리기 키트는 세로이고 3분 이하면 쇼츠로 본다.
  - 위치: `qa.py`, `upload.SHORTS_MAX`
- **BR-002 챕터**: 첫 줄은 00:00이고, 3개 이상이고, 각 10초 이상이다. 3분 미만 영상과 쇼츠에는 넣지 않는다.
  - 자리는 이 순서로 정한다: 이름 붙인 마커 → 번호 붙은 그래픽 제목("1. …") → 90~150초마다 가장 오래 쉰 곳.
  - 편집 메모처럼 보이는 마커 이름(BGM·자막 수정·다시 확인 등)은 챕터에서 빼고 알린다.
  - 위치: `upload.chapters`
- **BR-003 유튜브 글자 수**: 넘으면 유튜브가 저장을 거부하거나 무시하는 한도다.
  - 제목 100자, 설명 5000자, 태그 합계 500자(띄어쓰기 있는 태그는 따옴표 2자 + 태그 사이 쉼표로 센다), 해시태그 15개(넘으면 전부 무시됨).
  - 제목·설명에 `<` `>`를 쓸 수 없다. 자동 설명은 〈 〉로 바꾼다.
  - 쇼츠 해시태그 맨 앞에는 `#shorts`를 넣는다.
- **BR-004 다시 분석해도 사용자 편집본을 지키기**: 편집점 찾기를 다시 하면 다음과 같이 처리한다.
  - 기존 편집본은 하나도 지우거나 바꾸지 않는다.
  - 새 가편집은 `(새로 찾음)`을 붙인 이름으로 옆에 추가한다.
  - 자막은 새 받아쓰기로 바꾸되, 이전 상태는 '편집점 다시 찾기 전' 백업으로 남긴다.
  - 스타일로 자동 편집한 결과도 항상 새 편집본으로 추가한다.
  - 위치: `editor.reanalyze_project`
- **BR-005 업데이트는 사용자 설정·데이터에 손대지 않기**: `config.json`은 덮어쓰지도 지우지도 않는다. 파일이 없을 때만 넣는다.
  - `.venv`·`.git`과 작업 폴더(앱 폴더 안에 둔 경우 포함)는 교체·삭제·되돌리기 대상이 아니다.
  - 위치: `updater.KEEP`·`NEVER`·`_protected`
- **BR-006 썸네일 규격**: 롱폼은 1280×720, 쇼츠는 1080×1920이다.
  - 쇼츠 썸네일은 항상 쇼츠 전용 템플릿과 세이프존으로 만들고, 롱폼 레이아웃을 쓰지 않는다 (D-005).
  - 유튜브에 올리는 썸네일은 2MB 이하다. JPG 저장은 품질을 낮춰 2MB 안으로 맞추고, 올리기 키트가 크기·용량을 확인한다. 썸네일 편집기의 PNG 경고(`PNG_LIMIT`)와 올리기 키트 확인(`upload.THUMB_MAX`)은 같은 2MiB(2,097,152 바이트) 기준이다. A/B 묶음의 '모바일 비교' 한 장은 썸네일로 고르지 않는다.
- **BR-007 사용자가 고친 올리기 키트 내용 지키기**: 화면에서 고친 제목·설명·태그는 규칙(BR-003)을 넘어도 그대로 저장하고 알림만 띄운다.
  - 편집본을 다시 내보내도 고친 내용은 유지하고 "다시 만들기"를 권한다.
  - 내용을 바꾸는 것은 사용자가 누른 "다시 만들기"뿐이다.
- **BR-008 촬영본 묶기**: 2개 이상을 고른다. 원본은 지우지 않는다.
  - 순서: 파일 속 촬영 시각 → 파일 수정 시각 → 파일 이름(자연 정렬).
  - 화면 규격(코덱·크기·fps·방향)이 모두 같으면 화면은 화질 손실 없이 이어 붙이고, 소리는 파일 길이에 맞춰 다시 만든다. 다르면 가장 많은 규격으로 다시 만든다.
  - 결과는 `묶음_YYYYMMDD_<제목>.mp4`이고, 이어서 편집점 찾기까지 한 작업으로 한다.
- **BR-009 YouTube가 막을 때**: 자동으로는 엔진을 최신으로 바꾼 뒤 한 번만 다시 받는다.
  - 로그인 정보(쿠키)는 사용자가 '로그인 정보로 받기'에서 브라우저(크롬·엣지·웨일·파이어폭스)를 골랐을 때만 그 브라우저에서 읽는다 (D-009·D-036). 실패 카드의 브라우저 고르기도 사용자가 누를 때만 쓴다.
  - 크롬·엣지·웨일은 브라우저가 켜져 있으면 로그인 정보 파일이 잠겨 못 읽는다(yt-dlp #7271) → '창을 모두 닫고 다시'. Windows 크롬 127 부터는 새 보안 기능(App-Bound 암호화)으로 못 읽을 수 있다(#10927) → 엣지·파이어폭스를 권한다.
- **BR-010 하나씩**: 긴 작업은 한 번에 하나다. 겹치면 "다른 작업이 끝난 뒤에 다시 눌러 주세요"라고 알린다.
  - 앱도 하나만 켜진다. 이미 켜져 있으면 새로 열지 않고 그 창을 앞으로 가져온다. 같은 편집본을 두 곳에서 고치지 않게 하기 위해서다.
- **BR-011 자동 가편집 규칙** (AI 없이 규칙으로, D-003):
  - 롱폼: 군더더기(추임새·같은 말 반복·말 사이 약 1.2초 넘는 공백, NG 테이크·슬레이트·말더듬)를 뺀다.
  - 단어 시각이 있으면 앞뒤가 0.12초 이상 빈, 홀로 떨어진 추임새 단어도 롱폼·쇼츠 컷에서 뺀다 (앞뒤 빈 곳의 절반, 0.1초까지 함께).
  - 쇼츠: 20~55초 구간 3개를 서로 겹치지 않게 고른다. 점수는 강조 표현("꿀팁"·"중요"…), 소리 큰 순간, 말 밀도, 첫 문장 훅으로 매긴다. 앞 말에 기대는 첫 문장('그래야…')은 덜, 순서를 여는 첫 문장('자, 두 번째 포인트는…')은 더. 경계는 문장에 맞춘다 (BR-061 — 끝 문장 +5초·앞 시범 10초까지 늘 수 있음).
  - 영상 밖 말은 BR-060 대로 자르거나 뺀다.
  - 스타일이 있으면 그 편집 값(공백·줌 컷·자막 위치와 색)을 쓴다. 소리 크기는 유튜브 기준 범위(-14~-13 LUFS) 안으로만 따른다 (BR-022).
- **BR-012 '가편집 다시 만들기'의 범위**: `auto: "rough"` 표시가 있는 편집본만 처음 상태로 바꾼다. 사용자 확인을 받고, Ctrl+Z로 되돌릴 수 있다.
  - 복제하거나 이름을 바꾼 편집본은 표시가 지워져 사용자 편집본이 된다. 이 편집본과 스타일 가편집은 그대로 둔다.
- **BR-013 자막 나누기** (새 편집 프로젝트·편집점 다시 찾기·편집실 '자막 한 줄씩 나누기', D-023):
  - 자막은 언제나 한 줄이다. 쇼츠형: 13글자(띄어쓰기 빼고)·2.2초까지. 롱폼형: 17글자·3초까지.
  - 단어 사이에서만 나눈다. 단어 시각이 있으면 시작·끝은 첫 단어 시작·마지막 단어 끝이다. 없으면(예전 받아쓰기·고친 글) 띄어쓰기에서 나누고 시간은 글자 수대로(`captions.weight`: 한글 1·영어·숫자 0.5·문장부호 0, 낱말마다 1~12) 나누며, 조용한 곳(`analysis.json` silences)이 있으면 그 앞뒤에 낱말 사이를 맞춘다.
  - 한 단어가 혼자 한도보다 길면 그 단어만 따로 둔다. 0.6초보다 짧은 자투리와 3글자 이하 낱말 하나짜리 자막은 되도록 앞뒤와 합친다. 그래도 0.5초도 안 되게 스치는 자막은 한도의 1.5배까지 넘겨서라도 합친다(문장 끝·1.2초 넘게 쉰 곳은 넘지 않음). 1.2초 넘게 쉰 곳은 묶지 않는다.
  - 문장 끝(마침표가 없어도 '~요·~니다·~죠'로 끝나면 문장 끝으로 봄 — 한 자막에 두 문장을 되도록 안 넣음) > 이음말('그래서·그러면') 앞 > 말끝(~요·~고·~서·~는데·~다·~해도)·쉼표 > 조사 뒤 순서로 끊기 좋다. 기대는 말('수·것·게·때문에·때') 앞, 꾸미는 말('첫·한·안'·'~던'·'갈') 뒤, 붙여 읽는 풀이말('해야 / 되고'·'받고 / 나서'·'오기 / 전에'·'등지게 / 되기'), 목적어와 짧은 풀이말('집중을 / 해야') 사이는 피한다. 용어 사전의 여러 단어 용어('퍼스트 터치')는 혼자 한도보다 길 때만 나눈다.
  - 세로 원본은 쇼츠형, 가로 원본은 롱폼형이다. 자막은 프로젝트의 모든 편집본이 함께 쓴다. 가로 원본 자막은 쇼츠 편집본에서 쇼츠형으로 다시 나뉘어 보인다(`sh`·`shn`). 글을 고쳐 낱말 수가 바뀌면 그 자막은 나누지 않는다.
  - 한 줄이 화면 폭의 90%(왼쪽·오른쪽 정렬이면 남은 쪽, 그래도 90%까지)를 넘으면 그 자막 글자만 줄인다(0.7배까지 · 한글 폭 어림은 보통 0.9em, Black 0.95em). 더 줄여야 하는 긴 자막은 크기 그대로 줄을 바꾼다.
  - '자막 한 줄씩 나누기'는 지금 글(고친 글)을 그대로 나누고, 이미 한 줄이고 짧은 자막은 글·단어 시각·줄바꿈까지 그대로 둔다(가로 원본이면 쇼츠에서 나눌 곳 `sh`·`shn`만 더함). 12글자 이하 자막에 직접 넣은 줄바꿈은 그대로 두고(예전 두 줄 자막은 12글자 넘을 때만 생겼음), 0.6초보다 짧거나 끝이 시작보다 앞선 자막은 나누지 않는다. 되돌리기 한 단계다.
  - 0.3초보다 짧은 자막 사이 빈틈은 앞 자막을 늘려 메운다. 합칠 수 없던 짧은 자막은 다음 자막 전까지 0.6초는 보이게 한다.
  - 노래방 효과는 단어를 실제로 말한 때에 채운다 (미리보기·내보내기 같음 · 두 줄 자막·띄어쓰기 여러 번도 같은 규칙). 편집실에서 글을 고쳐 낱말 수가 바뀌면 글자 수 비례로 돌아간다.
  - 위치: `captions.chunk`·`split_text`·`from_segments`, `editor._captions_of`·`oneline_captions`·`_shorts_parts`·`cap_fit`·`_karaoke`, `editor.html` `capParts`·`capFit`
- **BR-014 영상 출처 판단** (`source.describe`):
  - 직접 고른 출처·채널 > 받을 때·조회한 yt-dlp 채널 정보 > 소재 찾기 목록에서 고른 출처(받기 전 힌트) > 우리 채널 목록 기억의 영상 id > 제목 짐작(`guess`, 아래) > 파일 이름 꼴(`YYYYMMDD_영상id11자_제목`이 아니면 내 촬영본).

  - 모든 %는 계획(저장 안 했으면 '방향 A 초안')대로 매주 올린다고 본 값이라고 적는다. 지금 속도(최근 4주)가 계획과 주당 0.25개 넘게 다르면 '지금 속도대로면' 확률을 같이 보인다 (요약 카드 · 가능성 탭 맨 위 · '이렇게 바꾸면' 첫 줄).
  - 구독자 예상은 P50 과 P10~P90 을 유효숫자 2자리로('약 9,000~13,000명').
  - 민감도는 두 끝을 각각 반올림해 그 차이로 적는다(%포인트). 3%p 안쪽이거나 반올림한 두 끝이 같으면 '거의 차이 없어요'. Claude 에게는 확률을 새로 지어내지 말고 화면 숫자만 인용하라고 지시한다.
- **BR-016 채널 숫자 새로 고침 예절** (`strategy.refresh`, D-024·D-026):

  - 요청 사이 0.75초, 채널 사이 2초 + 0~0.5초. 목록을 받은 지(`listedAt`) 3일 안인 채널은 건너뛴다('모두 다시' 제외 · RSS 만 받은 채널은 다시 받을 차례). 목록 단계를 쉬는 동안에는 RSS 를 받은 시각으로 건너뛴다. '이 채널만 새로 고침'은 10분 안에 받은 것만 건너뛴다. 전체 훑기(400개·한국어 원제)는 처음과 30일마다.
  - 오류 종류마다: YouTube 가 막음(봇 확인·403·429 · 한국어 원제 목록에서 막혀도) → 남은 목록 단계를 멈추고 6시간 쉼(RSS 는 계속) · 까닭 모를 실패 3곳 연달아 → 1시간 쉼(화면 [지금 다시 시도]로 풀 수 있음) · 인터넷 끊김(이름 풀이·연결 실패) → 두 곳 연달아면 이번 새로 고침만 멈추고 쉬지 않음 · 없는 채널(404·없음) → 그 채널만 실패(연달아 세지 않음). 막히면 엔진 최신화 뒤 한 번만 다시(BR-009). 쿠키는 쓰지 않는다. 화면 안내와 결과 알림은 저장한 까닭과 실제로 받은 수(목록·RSS 만·실패)대로.

  - 기록 줄의 구독자는 그날 목록에서 새로 받았을 때만 남긴다(RSS 만 받은 날의 예전 숫자를 오늘 날짜로 남기지 않음). 비교 데이터에 있는 채널을 처음 새로 고칠 때는 그 기록에서 출발해서, 목록을 못 받아도 조사 숫자가 사라지지 않는다(그때는 '조사 자료' 표시 그대로 · 첫 목록은 전체 훑기).
- **BR-017 점검 비교** (`strategy.evaluate`, D-026):

- **BR-018 가져올 점 점수와 성공 솔루션** (`strategy.takeaways`·`solution`, D-026):
  - 맞춤 점수 = 25% G(분류 무게 × 규모: 근거 채널이 우리보다 10배 안 1 · 20배 안 0.7 · 그 위 0.5) + 40% E(근거: 채널마다 배수를 영상 수로 줄여(ln 배수 × n/(n+6) · 20배 넘게 큰 채널은 절반) 가운데 값 → 0.5·log2 + 채널 하나 더할 때 0.15, 영상 6편 아래면 비례로 줄이고 5편 아래면 0.5까지) + 15% D(우리 방향·목표 시청자) + 20% F(일 크기).
  - 제목 공식·주제어·시리즈·참여·저장 규칙은 두 채널 이상 · 영상 5편 이상이어야 '상'(아니면 69까지). 조사 메모는 60까지, 목록 맨 아래 따로. 우리 계획이 이미 하고 있는 것('계획에 이미 있어요')은 뒤로.
  - 성공 솔루션의 '먼저 할 것'은 가져올 점을 맞춤 ÷ 일 크기로 고른 6개(분류마다 2개까지)이고 %를 붙이지 않는다 — 항목 하나의 효과는 따로 알 수 없어서. 항목마다 움직이는 쪽(조회수 올리기 · 구독 전환 올리기 · 쇼츠 운영 · 꾸준히 올리기 · 레슨 연계(구독 수와는 따로))만 적고, %포인트는 '계획을 바꾸면'(롱폼 +1 · 쇼츠 +2 · 조회 1.6배 · 전환 1.5배) 시나리오에만, 한 번씩 적는다.
  - 계획이 이미 하고 있거나 그 쪽 시나리오가 5%p 아래(쇼츠 +2 가 거의 차이 없음 등)인 쇼츠 늘리기·주기 조언은 솔루션에서 빼고, 롱폼 +1 이 5%p 넘으면 '쇼츠는 노출용 · 구독은 롱폼이 만들어요'를 한 줄로.

## 4. 불변식 (Invariants) — 절대 깨지면 안 되는 조건

- **저장은 바꿔 끼우기로 한다**: 임시 파일에 끝까지 쓴 뒤 `os.replace`로 바꾼다(Windows 잠금이면 재시도). 중간에 꺼져도 반쪽 파일이 남지 않는다. 대상은 편집 프로젝트·썸네일 디자인·올리기 키트·장면 후보 캐시·모델 파일·업데이트 파일이다. (예외: 스타일 파일, `KNOWN_ISSUES.md` I-003)
- **편집 프로젝트는 몰래 덮어쓰지 않는다**: 저장할 때 `rev` 판 번호를 비교한다. 그 사이 다른 창이 저장했으면 409(conflict)로 멈춘다. "그래도 저장"은 덮어쓰기 전 상태를 백업한 뒤에만 한다.
- **백업이 항상 남는다**: 자동 백업은 5분마다 한 벌씩 최근 10개를 남긴다. 태그 백업(편집점 다시 찾기 전·덮어쓰기 전·새 형식 변환 전)도 따로 10개를 남긴다.
- **깨진 파일은 지우지 않는다**: 편집 프로젝트가 깨졌으면 `<stem>.손상-<시각>.json.bad`로 옆에 남긴다. 그리고 저장 중이던 `.tmp`나 가장 최근 백업으로 복구한다. 썸네일 디자인은 빈 목록을 저장하지 않고, 직전 저장본을 `.bak`으로 둔다.
- **되돌리기는 문서 전체 스냅샷이다**: 편집실·썸네일 모두 바꾸기 전 문서 전체를 JSON으로 기록하고(`commit`/`pushUndo`), 최대 120단계까지 둔다. 모든 변경은 이 함수를 거친다.
- **보관함 원본은 앱이 바꾸거나 지우지 않는다**: 묶기·내보내기·썸네일은 모두 새 파일을 만든다. 결과물 이름이 겹치면 덮어쓰지 않고 ` (2)`·`_2`처럼 번호를 붙인다. 예외는 사용자가 누른 **학습용으로 옮기기**(지우지 않고 `refs/`로 옮김 · 풋살사관학교·내 촬영본은 한 번 더 확인 · 편집실 프로젝트에서 쓰는 영상은 안 옮김 · '보관함으로'로 되돌림)와 **MP4로 바꾸기**(바꾼 MP4 를 넣은 뒤 원본을 보관함 안 `바꾸기 전 원본` 폴더로 옮김 · 지우지 않음 · 확인 창을 거침)뿐이다. 확인 창의 [취소]는 언제나 아무것도 하지 않는다. 학습용 영상 파일은 사용자가 고른 지우기·'배운 뒤 영상 파일 지우기'로만 지운다.
- **학습용 영상은 편집 목록에 섞이지 않는다**: 보관함·편집점·편집실·썸네일·올리기는 `videos/`만 본다. 스타일 배우기·기획 분석만 `core.video_file`·`adir`로 학습용 영상을 찾는다 (D-022).
- **업데이트는 전부 아니면 원래대로다**: 받은 파일이 하나라도 manifest의 버전·sha256과 다르면 앱 폴더를 건드리지 않는다. 바꾼 뒤 새 버전이 안 열리면 이전 버전으로 되돌린다 (D-010).
- **서버는 이 PC 안에서만 열린다**: `127.0.0.1`에만 bind한다. Host·Origin을 검사한다. 영상·파일 이름 인자는 `editor.safe_name`으로 경로·드라이브·`..`를 거절한다. 유튜브 로그인 결과를 받는 서버도 `127.0.0.1` 빈 포트에 한 번만 연다(D-046).
- **유튜브 비밀은 사용자 폴더 밖으로 나가지 않는다**: 토큰·보안 비밀번호·세션 주소는 `~/.futsal-studio/youtube/`(DPAPI)·세션 파일(보호)에만 있고, 기록·응답·화면에 나오지 않는다. 키트 파일(`*_올리기.json`) 형식은 바꾸지 않는다.

## 5. 상태와 흐름

**영상 한 개의 흐름** (화면 1~7단계):

```
소재 찾기 → 보관함(videos/) ← 촬영 원본 넣기 · 촬영본 묶기
  → 편집점 찾기 (analysis/<stem>/, 보관함에 '분석됨')
  → 1차 가편집 자동 생성 (projects/<stem>.json)
  → 편집실 편집 (rev 증가·자동 백업) → 내보내기 (out/) → 자동 검수
  → 썸네일 (thumbnails/<stem>.json → out/<stem>_<라벨>_<n>.jpg)
  → 올리기 키트 (out/<…>_올리기.txt/.json) → 사용자가 YouTube Studio에서 직접 업로드
```
- 앱은 YouTube에 직접 올리지 않는다. 업로드 페이지를 열어 줄 뿐이다.
- 편집점을 다시 찾으면 편집본이 추가될 뿐 지워지지 않는다 (BR-004).

**편집본 표시 (`auto`)**: `rough`(자동 가편집) → 복제·이름 바꾸기 → 표시 없음(사용자 편집본). `style`(스타일 가편집)은 '가편집 다시 만들기' 대상이 아니다 (BR-012).

**업데이트 상태** (앱 폴더 `.update_pending`의 `state`):

```
(없음) → applying → installed ─ 다음 실행: import 확인 OK → 앱이 켜진 뒤 finish()가 지움 ("업데이트 완료")
            │                └ import 실패 · 켜지다 오류 · 60초 지나 2번 더 안 켜짐
            │                     → rolling_back → 되돌림 → .update_result(화면 알림) + .update_skip(그 버전 다시 권하지 않음)
            └ 바꾸는 도중 꺼짐 → 다음 실행 때 되돌림 (이 경우 .update_skip은 남기지 않음)
```

**작업(`JOB`)**: 없음 → 실행 중(이름 표시·진행률) → 끝(`result` 또는 `error`). 실행 중에 다른 작업을 요청하면 409다.

- **받아쓰기**: `large-v3-turbo`, CPU int8, 한국어, VAD 켬. 그래픽카드 없는 PC에서도 돌게 하기 위해서다 (D-003).
  - 단어 시각을 켠다. 용어 사전은 첫머리 힌트(`initial_prompt`, 약 120토큰)로, 설치된 faster-whisper가 받으면 매 구간 힌트(`hotwords`, 약 60토큰)로도 알린다. 앞쪽 용어부터 넣는다 (D-019).
  - 힌트 목록을 그대로 따라 쓴 구간(사전 순서대로 용어 4개 이상 · 확신 평균 0.5 미만 · 구간의 절반 이상)은 버린다. 말소리가 불분명한 곳에서 생긴다.
  - 사전 고치기는 낱말 경계에서만 하고, 뒤에 붙은 조사도 바뀐 말에 맞춘다 ('피버를' → '피벗을').
  - CPU 스레드는 최대 8개다. 모델은 한 번의 편집점 찾기(여러 영상)에서 한 번만 불러 쓰고, 끝나면 내려놓는다. 받아쓰는 동안 Windows가 절전으로 들어가지 않게 한다 (화면은 꺼질 수 있음).
- **다운로드**: 1080p 이하 mp4로 받는다. `videos/archive.txt`로 같은 영상을 다시 받지 않는다. 파일 이름은 `<업로드날짜>_<ID>_<제목>.mp4`다.
- **다운로드 엔진**: 3일마다 최신화하고, 실패했으면 하루 뒤 다시 한다. Deno는 2.3 이상이어야 한다 (D-008).
- **편집점**: 컷 후보는 -35dB 아래로 0.8초 이상 조용한 곳이다. 하이라이트는 소리가 중앙값보다 6dB 이상 큰 곳으로, 5초 간격을 두고 최대 10개다.
- **NG 테이크 판단**(작업 중): 앞 테이크와 3~60초 사이이고 글자가 70% 이상 비슷하면 NG 테이크로 본다. 사이에 슬레이트 말이 없으면 더 엄격하게, 사이에 다른 말이 없고 뒤 테이크가 앞 말의 80% 이상을 다시 해야 한다 (같은 말로 감싼 팁·나란한 설명을 지우지 않으려고). 말더듬은 1초 안에 다시 한 10자 이하의 같은 말이다 (`takes.py` 상수). NG 구간을 빼면 쇼츠 최소 길이보다 짧아지는 후보는 버린다.
- **소리 크기**: 기본 목표는 -14 LUFS(유튜브 재생 기준)다. 스타일 값은 -24~-9 LUFS로 제한한다. 검수는 목표와 2 LU 넘게 다르거나 피크가 -0.5 dBFS를 넘으면 '주의'다.
- **스타일 → 편집 값**: 말 사이 공백 기준은 p75 × 0.9로, 0.12~0.8초로 제한한다. 줌 컷은 1분에 0.3번 이상일 때만 쓰고, 배율은 1.08~1.6배다. 자막은 레퍼런스 화면의 25% 이상에 있었을 때만 켠다.
- **편집실 배치**: 왼쪽 패널 창 너비의 20%(220~300px) · 오른쪽 23%(280~340px) · 타임라인 창 높이의 40%(200px ~ 창 높이-240px). 끌어서 바꾼 크기는 그 PC 에만 기억하고, 가운데(미리보기·타임라인)는 360px 를 남긴다 (D-039). 타임라인에 V1·A1 이 다 안 보이면 열 때·크기가 바뀔 때 영상·소리 경계를 가운데로 굴린다. 오른쪽 패널이 310px 이하면 믹서 줄 58px (D-043).
- **편집실**: 고친 뒤 0.6초 안에 자동 저장한다. 백업은 5분마다 최근 10개를 남기고, 되돌리기는 120단계다. 내보내기 프리셋은 유튜브 1080p(crf 19) · 고화질 4K(crf 18) · 가벼운 720p(crf 23)다.
- **그래픽카드 인코더**: nvenc → qsv → amf 순서로 짧게 시험해 보고 되는 것을 쓴다. 실패하면 libx264로 간다.
- **썸네일**: 장면 후보는 16장이다(같은 화면은 dHash 거리 10 이하, 3장까지 · 후보끼리 영상 길이 5% 넘게 떨어짐). 화면 높이 8%보다 작은 얼굴(멀리 있는 선수)은 무시한다. 선수는 확률 0.35, 공은 0.2 이상. 흔들림 0.6 넘는 장면은 절반, 머리가 위로 잘린 장면은 0.7배, 박힌 글자는 넓이 1%마다 6% 감점(0.35배까지). 자동 보정은 밝기 평균 0.48·채도 1.24배를 목표로, 양 끝 0.5% 를 늘이되 한 채널에 40 이상 옮기지 않는다. 모델 받기에 실패하면 10분 동안 다시 시도하지 않는다 (D-014). JPG는 품질 0.93부터 낮춰 2MB 안으로 맞춘다.
- **올리기 키트**: 제목 후보는 3~5개다. 자동 챕터는 90~150초 간격이고, 챕터 제목은 20자 이내다. 해시태그는 3개(쇼츠는 `#shorts` 더함)다. 기본 태그는 `upload.BASE_TAGS`(풋살·풋살사관학교·최경진 감독…)다.
- **촬영본 묶기**: fps가 1% 안이면 같은 것으로 본다(휴대폰 가변 fps). 다시 만들 때는 최대 4K, 소리는 48kHz다. 시작 전에 디스크 공간을 확인한다.
- **업데이트**: 되돌리기 복사본은 최근 3개를 둔다. 업데이트 직후 60초 동안은 다시 눌러도 실패로 세지 않는다(백신 검사·창 준비가 느릴 수 있음). 그 뒤에도 2번 더 안 켜지면 되돌린다.
- **쇼츠 조회수 세기**: YouTube 는 2025년부터 쇼츠 조회에 다시 보기도 센다. 그래서 쇼츠 조회수는 커 보이고 구독 전환(1,000회당 구독)은 롱폼보다 훨씬 낮다 (2026-10-07 비교 채널 10곳: 롱폼 약 7.4명 · 쇼츠 약 0.13명). 채널 전략의 가능성 계산은 이 차이를 그대로 쓴다 (D-025).
