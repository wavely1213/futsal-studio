# SECURITY_GUIDELINES.md — 보안 지침

> **목적**: 이 앱은 회원·서버·DB가 없는 로컬 데스크톱 앱이다. 하지만 사용자 PC에서 로컬 서버를 열고,
> 인터넷에서 실행 코드(업데이트·Deno·모델)를 받아 설치하며, 촬영 영상(얼굴·목소리)과 브라우저 쿠키를 다룬다.
> 보안 사고 한 번이 사용자 PC와 채널 신뢰를 무너뜨린다. 로컬 서버 API·파일 경로·다운로드·업데이트·쿠키·개인정보를
> 다루는 모든 작업 전에 이 문서를 읽는다.

---

## 1. 시크릿 관리

- API 키·비밀번호·토큰·DB 접속 정보는 **코드·커밋·로그·문서·주석 어디에도 남기지 않는다.**
- 시크릿은 환경변수(또는 시크릿 매니저)로만 주입한다. 현재 앱에는 **시크릿이 없다**.
  - API 키·서버·로그인이 없다. `config.json`에는 공개값(채널 주소·작업 폴더·업데이트 주소)만 있다.
  - 예외 하나: 사용자가 '클로드 계정으로 쓰기'의 고급 칸에 붙여 넣은 로그인 코드(`claude setup-token`, `sk-ant-oat…`)는 `~/.futsal-studio/claude_token`(사용자 폴더, 앱 폴더·`config.json` 밖, 권한 600)에 둔다. 자식 프로세스 환경 변수 `CLAUDE_CODE_OAUTH_TOKEN`으로만 넘기고 기록·응답·화면에 내보내지 않는다. [지우기]로 지운다 (D-021).
  - 환경변수는 `FUTSAL_*`뿐이고 시크릿이 아니다(`PROJECT_CONTEXT.md` 5절).
  - 유일한 자격 증명은 개발 PC의 GitHub 푸시 권한(`wavely1213/futsal-studio`)이다. 이 권한은 곧 **모든 사용자 PC에 코드를 설치하는 권한**이다(3번 참고). 토큰을 저장소·문서·로그·`RELEASE_TRAILER`에 넣지 않는다.
- 저장소는 공개다(업데이트가 인증 없이 raw·archive 주소로 받는다). 추적 파일은 `tests/`·`manifest.json`을 빼고 모두 사용자 PC로 배포된다. 그래서 저장소에 들어간 것은 곧 공개·배포된 것이다.
- 지금은 `.env`를 쓰지 않아 `.gitignore`에도 없다. 새 시크릿이 필요한 기능(예: YouTube API 직접 업로드)을 만든다면:
  - 변수명만 정하고 값 설정은 소유자에게 요청한다.
  - 둘 곳은 소유자와 정한다. 앱 폴더와 `config.json`은 안 된다. 앱 폴더는 업데이트로 바뀌고, `config.json`은 공개 저장소의 배포 파일이다.
- **브라우저 쿠키(YouTube 로그인)는 시크릿으로 취급한다.**
  - 사용자가 '로그인 정보로 받기'(또는 실패 카드)에서 브라우저를 골랐을 때만 `cookiesfrombrowser=(<고른 브라우저>,)`로 yt-dlp에 넘긴다(`core.list_videos`/`download`). 서버는 `trouble.BROWSERS`(chrome·edge·whale·firefox) 안의 값만 받고 나머지는 400 — yt-dlp 의 `브라우저:프로필` 꼴(경로)을 요청으로 넘기지 않는다 (D-028).
  - 쿠키를 파일·`config.json`·로그로 복사하지 않는다.
  - 기본값을 켜짐으로 바꾸거나 자동으로 켜지 않는다.
- **코드에서 하드코딩된 시크릿을 발견하면 즉시 보고한다** (이미 커밋됐다면 키 회전 필요 — 소유자 판단).

## 2. 입력 검증 — 모든 외부 입력은 불신한다

- 불신할 입력은 다음과 같다.
  - 로컬 서버로 오는 모든 HTTP 요청: 사용자가 브라우저로 연 아무 사이트나 `127.0.0.1:8765`로 요청을 보낼 수 있다.
  - YouTube에서 온 제목·채널 정보, 받은 파일 이름, 받아쓰기 결과
  - 사용자가 가져온 영상·이미지·음악(깨진 파일일 수 있음)
  - 인터넷에서 받은 zip·실행 파일·모델
- 검증 도구/패턴: 라이브러리 없이 `app.Handler`가 경계에서 다음 순서로 막는다. 새 API도 같은 순서를 따른다(`ARCHITECTURE.md` 7절 7번).
  1. Host 확인(GET·POST)
  2. Origin 확인(POST, 3번 참고)
  3. 이름 인자 검사: `editor.safe_name()`/`video_path()`가 경로·드라이브·`\\서버`·`..`·`:`·NUL을 거절한다. (빈틈: `/api/thumb/cut` 의 `src` 안 `/frame?name=` 은 검사 없이 `thumb.grab` 으로 간다 — `KNOWN_ISSUES.md` I-021)
  4. 파일을 읽거나 내주기 전에 `resolve()`한 뒤 허용 폴더 안인지 확인한다. 허용 폴더는 `core.VIDEOS`·`core.ANALYSIS`·`editor.ASSETS`·`core.OUT`·`thumb.ASSETS`·`style.STYLES`·`fonts/`·`refs.root()`(학습용 영상)다. 학습용 영상은 화면에서 받은 파일 이름(`safe_name`)과 `refs.json`의 폴더 이름(`refs._safe_folder`: 경로 문자·`..`·끝 공백/점 거절)으로만 경로를 만든다.
- **SQL 인젝션**: DB가 없다(JSON 파일 저장). 같은 자리의 위험은 **명령·필터 인젝션**이다.
  - 외부 프로그램은 항상 인자 목록으로 `core.run()`/`editor.run_killable()`을 통해 실행한다.
  - `shell=True`·`os.system`·`eval`은 쓰지 않는다(현재 0건).
  - 예외는 Windows 바로가기를 만드는 PowerShell(`app.ensure_shortcut`) 하나다. 값을 작은따옴표 escape(`q()`)한 뒤 `-EncodedCommand`로 넘긴다. 사용자 입력을 넣지 않는다.
  - ffmpeg 필터 문자열에 사용자 경로·글자를 직접 넣지 않는다.
    - 자막은 임시 폴더의 `subs.ass`(상대 이름)로 넘기고, 글자는 `editor._ass_text()`로 `{}`·`\`를 무력화한다.
    - concat 목록은 고정 이름(`seg0000.mp4`)이나 `bundle._q()`로 쓴다.
- **XSS**: UGC 대신 밖에서 온 글자를 출력한다. YouTube 제목, 파일 이름, 받아쓰기, 스타일·편집본 이름이다.
  - `innerHTML`에 넣을 때는 각 HTML의 `esc()`로 감싼다(`ui.html`·`editor.html`·`thumb.html`).
  - HTML을 허용하는 곳이 없어 새니타이저는 쓰지 않는다. 필요해지면 `DEPENDENCY_POLICY.md` 절차를 따른다.
- **업로드 파일**: 확장자·MIME·크기를 검증하고, 실행 가능 파일을 거부하며, 저장할 때 파일명을 새로 만든다. 현재 처리 방식은 다음과 같다.
  - 편집실 가져오기(`/api/edit/upload`): 확장자를 `editor.MEDIA_EXTS`(영상·음악·이미지)만 허용하고, 파일 이름의 금지 문자를 바꾼다. 같은 이름이 있으면 `_1`을 붙여 덮어쓰지 않는다.
  - 썸네일 그림(`/api/thumb/upload`): `img_<시각>.png|jpg`로 새 이름을 붙인다. 필요하면 PIL로 회전을 적용하고 긴 변 3000px로 줄인다.
  - 크기 제한은 없다(사용자 본인 PC의 파일). 새 업로드 경로를 만들 때도 확장자 허용 목록과 새 이름 규칙을 지킨다.
- **받은 zip 풀기**: `updater._rel()`이 절대 경로·`..`·드라이브·역슬래시·끝 공백/점 이름과 링크를 거절한다(zip slip 방지). 다른 곳에서 압축을 풀 때도 같은 함수를 쓴다.

## 3. 인증·인가

- 인증 방식: 로그인이 없다(한 PC·한 사용자 로컬 앱). 대신 다음 규칙으로 "이 PC의 앱 창에서 온 요청"만 받는다.
  - 서버는 `127.0.0.1`에만 bind한다. `0.0.0.0`이나 다른 포트·서버를 새로 열지 않는다.
  - Host 헤더가 `127.0.0.1:PORT` 또는 `localhost:PORT`여야 한다. DNS 리바인딩으로 다른 사이트가 응답을 읽는 것을 막는다.
  - POST는 Origin이 같은 출처여야 한다. 다른 사이트의 몰래 요청(CSRF)을 막는다.
  - Origin 없는 POST는 허용한다. 같은 PC의 프로그램(`app._focus_running`)이 쓰기 때문이다. 같은 사용자의 로컬 프로세스는 믿는다는 전제다.
- **GET은 읽기 전용으로 둔다.** 다른 사이트의 `<img src="http://127.0.0.1:8765/…">`도 Host가 맞아 통과한다. 응답을 읽지는 못하지만 동작은 일어난다.
  - 지우기·저장·작업 시작·폴더 열기처럼 상태를 바꾸는 동작은 반드시 POST로 만든다.
  - 지금 GET이 하는 쓰기는 캐시 생성(`/frame`·`/api/edit/thumbs.jpg` 등 · 채널 전략 `strategy/forecast.json`·`solution.json`)뿐이다. 사용자 기록(`strategy/state.json` 등)은 GET 에서 쓰지 않는다.
  - 계산이 무거운 GET(채널 전략 `/api/strategy/forecast`·`/api/strategy/preview`)은 한 번에 하나만 계산한다(`strategy._FC_LOCK`). 가능성 입력은 자료 받은 시각 기준이라 같은 자료면 캐시를 쓰고, 미리 보기는 저장·캐시를 하지 않는다 (D-026).
- 비밀번호를 다루지 않는다. 다룬다면 bcrypt/argon2 해싱을 쓴다(직접 구현 금지, 검증된 라이브러리 사용).
  - YouTube 계정 비밀번호를 앱이 받거나 저장하는 기능은 없다.
  - **YouTube 봇 확인을 사용자 자격 증명으로 자동 우회하지 않는다.** 막히면 엔진을 최신으로 바꿔 한 번만 다시 시도한다. 쿠키는 사용자가 직접 켤 때만 쓴다(`DECISION_LOG.md`).
- **인가는 모든 요청에서 서버 측 검증**: IDOR 대신 **경로 탈출**을 막는다.
  - 화면이 목록에 보여 준 이름만 보낸다고 믿지 않는다. 서버가 2번의 이름 검사와 허용 폴더 확인을 매번 한다.
  - 폴더·파일·주소 열기는 정해진 목록에서만 한다.
    - `/api/open`: `videos`·`analysis`·`out` 중 하나
    - `upload.reveal`: `core.OUT` 안 파일 이름
    - `upload.open_studio`: 고정 주소 `STUDIO_URL`
- 관리자 기능·권한 등급은 없다. 사실상의 관리자는 **배포하는 사람(= `main` 푸시 권한)**이다.
  - `manifest.json`의 sha256은 받는 중 손상·섞임을 막을 뿐 **서명이 아니다**. 저장소 쓰기 권한을 가진 사람은 모든 사용자 PC에서 코드를 실행할 수 있다.
  - 그래서 배포는 소유자 승인 후 `release.sh`로만 한다(`DEVELOPMENT_RULES.md` 8번).

## 4. 개인정보

- 수집하는 개인정보 목록: **앱이 밖으로 보내거나 모으는 개인정보는 없다**(분석 이벤트·원격 로그·통계 없음). 사용자 PC 작업 폴더 안에는 다음이 쌓인다.
  - 촬영 영상: 감독·수강생의 얼굴과 목소리
  - 받아쓰기 대사: `analysis/<영상>/transcript*`
  - 얼굴 위치·크기·표정 점수: 장면 후보 캐시에 저장한다. 얼굴이 **누구인지 식별하지 않고** 특징값도 저장하지 않는다. 모델은 로컬 onnxruntime으로 돌린다.
  - 우리 채널 제목·조회수(`channel_cache.json`, 공개 정보)
- 얼굴 식별(누구인지 알아보기)이나 생체 특징값 저장을 새로 넣으려면 소유자 결정을 받고 `DECISION_LOG.md`에 기록한다.
- 밖으로 나가는 것은 다음뿐이다.
  - YouTube 요청(사용자가 켜면 쿠키 포함)
  - 다운로드 서버 요청: PyPI·GitHub·Deno·Hugging Face·jsDelivr·i.ytimg(`PROJECT_CONTEXT.md` 6절)
  - Claude 질문: 사용자가 '복사' 버튼으로 직접 claude.ai에 붙여 넣는다. 받아쓰기 요약이 들어간다.
  - 클로드로 더 깊게 보기(D-021): 사용자가 스타일 카드의 버튼을 누를 때만, 사용자 PC의 Claude Code CLI가 사용자 본인 클로드 계정으로 Anthropic에 보낸다. 들어가는 것은 레퍼런스(다른 유튜버) 영상의 기획 판단·대사 발췌(처음 60초 + 본편 8군데, 모두 약 6000자까지)·화면 자막 글자 목록·장면 그림 최대 8장이다. 우리 촬영본은 보내지 않는다.
    - 실행 제한(빈 임시 폴더, 도구는 Read 만 또는 없음, 설정 파일·MCP·세션 저장 끔, 권한 질문 거절)은 CLI 판 확인(`claude --help`)이 실패해도 빼지 않는다(fail closed). 예전 판이 그 옵션을 모르면 실행하지 않고 '새 판으로 바꿔 주세요'라고 안내한다. 레퍼런스 대사는 남이 만든 글(프롬프트 주입 가능)이라 도구 제한을 늘 유지해야 한다.
    - 실행은 빈 임시 폴더에서 Read 도구만(그 폴더 안), 권한 질문은 모두 거절, 세션·설정 파일·MCP 끄기. 자식 환경에서 `ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN`을 지운다(있으면 계정 로그인보다 먼저 쓰여 요금이 나감).
    - `studio.log`에는 결과 종류(성공·로그인 필요·한도 등)만 남기고 프롬프트·대답·토큰은 남기지 않는다.
  - 채널 전략의 [클로드로 더 깊게 보기](D-024): 버튼을 누를 때만, 같은 Claude Code CLI 실행 제한으로 보낸다. 들어가는 것은 공개 채널 숫자(구독자·보통 조회수·주기)·경쟁 채널 이름·가져올 점과 근거 숫자·우리 전략 글(방향·대상·차별화·시리즈)·가능성 요약이다(약 6000자). 영상·대사·장면 그림은 보내지 않는다. `studio.log`에는 결과 종류만.
  - 채널 전략은 YouTube 공개 RSS·목록만 읽는다(키·쿠키 없음). 채널 설명은 '레슨 안내·문의 경로·협찬' 표시만 저장하고 원문(이메일·전화)은 남기지 않는다. `studio.log`에는 채널 이름과 결과 종류만 남긴다.
  - 이 내용을 자동으로 전송하도록 바꾸지 않는다. 바꾸려면 소유자 결정이 필요하다.
- 개인정보는 **로그·에러 메시지에 남기지 않는다.**
  - `studio.log`는 문제가 생기면 사용자가 관리자에게 보내는 파일이다. 쿠키·계정 정보·대사 전문을 쓰지 않는다.
    - 작업 실패의 영어 원문(`원문 · …`, 400자까지)과 오류 위치(`오류 위치 · …`)를 남긴다(D-029). 위치는 우리 파일 이름·바깥 라이브러리 '패키지/파일'만 쓰고 전체 경로는 쓰지 않는다. 원문에는 파일 경로(사용자 이름이 든 작업 폴더 등)가 들어갈 수 있다 — 지금도 studio.log 첫머리에 작업 폴더 경로가 있다. 쿠키 오류 원문은 쿠키 값이 아니라 쿠키 파일 위치·이유만 담는다.
  - 파일 이름과 원인 정도만 쓴다. 경로에 Windows 사용자 이름이 들어갈 수 있다는 점을 염두에 둔다.
- 회원 탈퇴 대신 **삭제**를 안내한다. 회원은 없다. 앱 폴더를 지워도 다음 두 곳은 남으므로, 완전 삭제를 안내할 때는 함께 알려 준다.
  - 작업 폴더: `config.json`의 `workspace`, 기본 `~/풋살사관학교_작업`
  - `~/.futsal-studio/`: 엔진 기록·Deno·모델
- 법적 요구사항(개인정보처리방침, 수강생 촬영 동의, 레퍼런스로 받은 다른 유튜버 영상의 저작권·약관)의 판단·결정은 소유자 몫이다. AI는 관련 작업 시 사실 확인이 필요한 지점을 짚어주기만 한다.

## 5. 기타 규칙

- **Rate limiting**: 로그인·가입 엔드포인트가 없어 해당 없다. 대신 다음 두 가지를 지킨다.
  - 긴 작업은 `start_job`으로 한 번에 하나만 돌린다(겹치면 409).
  - 외부 재시도는 횟수와 간격을 제한한다.
    - YouTube가 막으면 엔진 최신화 후 **1회만** 다시 시도한다.
    - 엔진 최신화나 Deno 설치에 실패하면 하루 동안 다시 하지 않는다(`ENGINE_RETRY`).
    - 얼굴 모델 다운로드에 실패하면 10분 동안 다시 하지 않는다(`face.RETRY`).
  - YouTube를 반복해서 두드리는 루프나 우회 로직을 만들지 않는다.
  - 채널 전략 새로 고침(BR-016): 사용자가 누를 때만 작업 하나로, 요청 사이 0.75초·채널 사이 2초+흔들기, 목록을 받은 지 3일 안인 채널은 건너뜀, YouTube 가 막으면(봇 확인·403·429) 6시간·까닭 모를 실패가 3곳 연달아면 1시간 목록 단계를 쉼(사용자가 [지금 다시 시도]로 풀 수 있는 것은 1시간 쉼뿐), 인터넷이 끊기면 그 새로 고침만 멈춤. 자동 요청은 8단계를 열 때 우리 채널 숫자 하루 한 번뿐(설정에서 끔 · 쉬는 중이면 건너뜀). 주기적 자동 새로 고침은 만들지 않는다.
  - 받은 RSS(XML)는 2MB까지만 읽고, `<!DOCTYPE`·`<!ENTITY`가 들어 있으면 해석하지 않고 버린다(XML 폭탄·외부 개체 대비). 응답의 제목·채널 이름은 화면에 `esc()`로만 넣는다.
- **CORS**: CORS 헤더를 보내지 않는다. 그래서 다른 출처의 스크립트는 응답을 읽지 못한다. `Access-Control-Allow-Origin`을 추가하지 않는다(`*` 금지).
- **에러 응답**: 스택 트레이스·쿼리를 응답에 넣지 않는다.
  - 예외 메시지가 곧 화면 문구다. 사용자 문장으로 쓴다(`CODING_STANDARDS.md` 5번).
  - `traceback.print_exc()`는 표준 출력에만 쓴다(사용자 PC에서는 보이지 않음).
- **받은 실행 코드·모델의 무결성**: 새로 받는 실행 파일·모델에는 고정 주소와 크기·sha256 확인을 붙인다. 확인한 뒤에만 임시 파일을 제자리로 옮긴다(`os.replace`). 현재 상태는 다음과 같다.

  | 대상 | 확인 방식 |
  |---|---|
  | 앱 업데이트 | 파일별 sha256(`manifest.json`)·zip 검사·문법 확인·새 실행기 `--selftest`, 실패하면 되돌림 |
  | Deno | 같은 서버의 `.sha256sum`과 실행 확인(`deno --version` ≥ 2.3) |
  | 얼굴·표정 모델 | 고정 커밋 주소, 크기·sha256 고정값 |
  | 기획 분석 모델(OCR 글자 찾기·한국어 읽기·글자 목록, YAMNet) | 고정 태그·커밋 주소, 주소마다 크기·sha256 고정값 (`avmodels.SPECS`) |
  | Claude Code CLI | 앱이 받지 않음. 사용자가 [설치하기]로 Anthropic 공식 설치 명령을 보이는 창에서 직접 실행 |
  | 누끼 모델(rembg 릴리스) | **크기·sha256 확인 없음** (`thumb._model`). `KNOWN_ISSUES.md` I-023 |
  | yt-dlp·pip 패키지·Whisper 모델 | pip와 Hugging Face의 기본 동작에 맡긴다 |

- **의존성 취약점**: `DEPENDENCY_POLICY.md` 참고. audit 경고 발견 시 보고.
- 밖으로 나가는 통신은 모두 HTTPS다. 업데이트·다운로드 주소를 `http://`로 바꾸지 않는다(`updater.download_and_install`은 형식상 `http`도 받으므로 주소 쪽에서 지킨다).
- 로컬 서버는 루프백 전용 HTTP다. 쿠키·세션을 쓰지 않는다.

## 6. AI 작업 시 보안 체크리스트

로컬 서버 API, 파일 경로, 외부 프로그램 실행, 다운로드·업데이트, 쿠키·개인정보 관련 코드를 작성/수정했다면 완료 보고 전에 확인한다.

- [ ] 새 입력 경로에 서버 측 검증이 있는가
  - 새 API가 Host·Origin 검사 뒤에 있는가
  - 이름 인자를 `editor.safe_name()`으로 검사하는가
  - 상태를 바꾸는 동작이 POST인가
- [ ] 새 조회/수정 경로가 `resolve()` 후 허용 폴더 안인지 확인하는가
- [ ] 쿠키·계정·개인정보(대사 전문 포함)가 코드·로그·`studio.log`에 남지 않는가
- [ ] 외부 프로그램을 인자 목록으로 실행하는가
  - shell을 쓰지 않는가
  - ffmpeg 필터 문자열에 사용자 글자·경로를 그대로 넣지 않는가
- [ ] 밖에서 온 글자(YouTube 제목·파일 이름·받아쓰기)를 `innerHTML`에 넣을 때 `esc()`를 거치는가
- [ ] 새로 받는 실행 파일·모델에 고정 주소 + 크기·sha256 확인이 있는가
- [ ] `updater.py`·`release.sh`를 고쳤다면 `tests.test_update`와 `python3 updater.py --selftest`가 통과하는가

보안상 애매한 트레이드오프(예: 편의 vs 보안)는 선택지를 제시하고 소유자가 결정한다.
